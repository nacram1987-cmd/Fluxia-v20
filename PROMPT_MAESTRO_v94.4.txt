## PRINCIPIO #2: manifest Y canal.json SIEMPRE ACTUALIZADOS A VERSION NUEVA
**OBLIGATORIO EN CADA ENTREGA.** Estos archivos definen qué versión descarga el cliente.

### manifest.webmanifest
**SIEMPRE actualizar:**
```json
{
  "name": "Fluxia BETA vX.X-LAB",
  "short_name": "Fluxia",
  "start_url": "./index.html",
  ...
}
```
Si no cambias el `name`, el cliente no sabe que hay versión nueva.

### fluxia-canal.json
**SIEMPRE actualizar (es el CONTROL DE VERSIONES de la app):**
```json
{
  "app": "Fluxia",
  "lab": "index.html",
  "lab_version": "vX.X-LAB",
  "stable": "index.html",
  "stable_version": "vX-1.X-ESTABLE",
  "timestamp": "ISO8601"
}
```
- `lab_version` = la versión LAB que GitHub Pages va a descargar
- Si no cambia, el cliente cree que sigue en v94.3

**REGLA DE ORO:** Si olvidas actualizar manifest y canal.json, el usuario seguirá en la versión anterior aunque hayas subido los archivos.

## PRINCIPIO #8: REGLAS DE v94.4 ESPECÍFICAS

### Ingresos Arrastrados
- Función: `arrastrarIngresosCobrados(mesActual, mesPrevio)`
- Storage: `ARRASTRADOS_KEY = 'fluxia_arrastrados_v94'`
- Lógica: Buscar ingresos cobrados en mes anterior (pagadoEl ≠ null), copiar con nuevo ID
- Hook: En `sincronizar()`, ANTES de `detectarCiclos()`
- No duplicar: Verificar si ya existe en array de arrastrados

### Enlace Automático de Puentes
- Función: `enlazarPuenteManualAuto(puente, movimientos)`
- Lógica: Para cada puente (tipo='puente', origen='excel'):
  1. Buscar salidas que coincidan (nombre similar, ±5% importe)
  2. Buscar entradas que coincidan
  3. Si sumaEntradas - sumaSalidas ≈ 0 (±10%), enlazar TODO
  4. Marcar movimientos con `cicloDe = puente.id`
- Hook: En `sincronizar()`, ANTES de `detectarCiclos()`

### Exclusión de Ciclos del Total
- Cambio: `ingresosDe(mes)` filtra `!it.cicloDe`
- Resultado: Totales automáticamente excluyen ciclos
- NO rompe ingresos manuales (Excel) que NO sean ciclos
